# 需求與業務規則

## 1. 背景與痛點

店內食材各有不同的保存期限，品項也經常上下架。每次到期都要換標籤，目前流程是：

1. 到冷藏區看標籤，確認哪些品項要換。
2. 回到辦公室寫標籤（標籤機放在辦公室）。
3. 再走回冷藏區換標籤。

來回跑很多趟，也容易漏看或算錯日期。

本系統的目標是：**員工在電腦前就能快速掌握每個品項的狀態，減少來回確認的次數。**

標籤是手寫的，系統不負責印標籤。

## 2. 使用情境

- 單店使用，部署在店內一台電腦上。
- 員工透過瀏覽器操作，不需要登入。
- 資料量小，使用 SQLite 儲存。

## 3. 名詞定義

| 名詞 | 說明 |
|---|---|
| 品項 | 需要追蹤換標的食材或醬料，例：火腿 |
| 解凍日 | 換標當天，貼紙上寫「解凍」 |
| 解凍天數 | 冷藏解凍所需天數，顯示為「解 X」 |
| 開封日 | 解凍日 + 解凍天數，貼紙上寫「開封」 |
| 保存天數 | 開封後的保存期限，顯示為「放 Y」 |
| 丟棄日 | 開封日 + 保存天數，貼紙上寫「丟棄」，系統中的到期日就是這個 |
| 層架 | 存放位置，數量可增減，預設 6 層，每層有名稱 |
| 新增方塊（+） | 每層最右邊的虛擬方塊，點擊後可在該層新增品項 |
| 排序 | 同一層內品項的先後順序，預設為新增順序，可透過拖曳更改 |

## 4. 日期規則

開封日 = 解凍日 + 解凍天數
丟棄日 = 解凍日 + 解凍天數 + 保存天數
剩餘天數 = 丟棄日 − 今天


範例（已與店家確認）：

| 品項 | 解 | 放 | 解凍日 | 開封日 | 丟棄日 |
|---|---|---|---|---|---|
| 火腿 | 1 | 2 | 10/28 | 10/29 | 10/31 |
| BBQ醬 | 1 | 7 | 10/28 | 10/29 | 11/05 |
| 鹽烤鱈魚 | 1 | 1 | 7/29 | 7/30 | 7/31 |

解凍天數允許為 0。

## 5. 狀態規則

| 剩餘天數 | 狀態 | 顯示文字 | 顏色 |
|---|---|---|---|
| ≥ 2 | 安全 | 還有 N 天 | 綠色 |
| 1 | 即將到期 | 剩 1 天 | 黃色 |
| 0 | 今天丟棄 | 今天丟棄 | 紅色 |
| < 0 | 已過期 | 已過期 | 紅色 |

## 6. 功能需求

### 6.1 層架

- 預設 6 層，可新增一層或移除最後一層。
- 移除層架時，該層必須是空的，若仍有品項則不允許移除，需先將品項移走或刪除。
- 每層最右邊有一個「+」方塊，點擊後可直接在該層新增品項。
- 層架名稱可點擊編輯，留空時使用「第 N 層」。
- 層架上的品項預設依新增順序排列，可透過拖曳更改順序。

### 6.2 品項

- **新增**：點擊某層的「+」，輸入品名、解凍天數、保存天數，解凍日為今天，品項加入該層最後面。
- **換標**：點選品項，解凍日更新為今天，開封日與丟棄日重新計算。
- **刪除**：需要確認。
- **移動**：
  - 可拖曳到其他層架，放在該層任一位置。
  - 同一層內可拖曳改變順序。
  - 拖曳只用於調整位置，新增一律透過「+」方塊。

### 6.3 狀態統計

- 畫面頂部顯示三個數字區塊：
  - 綠色（安全）：N 項
  - 黃色（即將到期）：N 項
  - 紅色（今天丟棄／已過期）：N 項
- 只顯示數量，不展開品項清單。

## 7. 非功能需求

- 所有員工都能操作，不需要權限區分。
- 日期計算由後端負責，前端只負責顯示與送出操作。
- 介面文字為繁體中文；程式碼的命名與註解以英文為主。

## 8. 不在範圍內（目前）

- 登入與權限管理
- 多店、雲端同步
- 通知推播（LINE、Email）
- 列印功能（標籤為手寫，列印暫不做）
- 直接列印標籤
